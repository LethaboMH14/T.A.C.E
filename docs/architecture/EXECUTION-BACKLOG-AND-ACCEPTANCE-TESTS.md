## 1. What the deliverable must prove

The judged vertical slice is **Autonomous Education Recovery Colleague** based on **synthetic** records for 36 fictional adult trainees and three fictional mentors. It must be possible to start with an authorized goal, perform *real computation and file operations*, generate a dependency-aware task plan, produce actual deliverables, independently catch a deliberately introduced intermediate defect, repair it within a bounded budget and recheck the saved result. The final screen should expose the real source rows, task transitions and versioned artifacts. No simulated send, no ungrounded confidence, no imaginary task logs.

The long-term platform is **universal**, with an education **domain pack** plugged into generic intake, planning, runtime, tool, event, verification and UI contracts.

### Eight demo outputs (actual files to persist)

1. `gap-analysis.csv` — source-backed per-trainee skill gaps, no unsupported trait inference.
2. `performance-summary.md` or HTML — computed cohort totals, distribution, missing-data flags, methodology and uncertainty.
3. `improvement-plan.json` and readable Markdown — action plan linked to verified gaps and skills.
4. `mentor-schedule.csv` — collision-free allocation respecting time windows and mentor capacity.
5. `unsent-message-drafts.md` — reviewable wording only; **never send** or mark sent.
6. `evidence-checks.json` — actual verifier results and source pointers, PASS/FAIL/UNKNOWN.
7. `repair-history.json` plus saved v1/v2 artifacts — failure, root cause, targeted change, independent recheck.
8. `final-manifest.json` and `events.jsonl` — artifact hashes, accepted tests, unresolved conditions and actual event chronology.

The input schema, file naming and algorithms must become versioned tests, not arbitrary strings in one prompt.

### P0.2 — source admission and artifact storage (scoped G03/G07)

- Implement a local-only **authorized synthetic source registry** with source ID/version/hash, schema validation and provenance row locators. Do not add arbitrary URL or cloud connector yet.
- Persist source manifest to a private run directory and use atomic write/rename for artifacts.
- Each artifact records producer task, input versions, content digest, MIME, run/tenant fixture scope, creation time and accepted criteria. Re-open file after write.
- Protect against path traversal/symlink escape, HTML/CSV formula injection, invalid row types and unexpectedly large files.

**Tests:** source unknown/stale/version altered, duplicate ID, file outside allowed directory, malformed CSV, replay/overwrite, read-back digest mismatch, zero/partial input.

**Done when:** real local file can be created/opened/hashed with source provenance, and missing source yields a typed BLOCKED outcome.

### P0.3 — real task DAG with proportional workers (scoped G04/G05/G06)

**First graph, actual typed nodes:**
```
admit_source
    ↓
compute_gaps
    ├──→ performance_report
    └──→ intervention_recommendations
                  ↓
              mentor_schedule
                  ↓
        draft_communications
                  ↓
       independent_verify
                  ↓ failed
           targeted_repair
                  ↓
       independent_reverify
                  ↓
             final_manifest
```
- Task IDs unique, dependsOn validated/acyclic, real capability handles, input/produced artifacts, one owner/worker and acceptance check per task.
- Planner chooses only tasks needed for goal: request just a report → no scheduling; request schedule → include relevant dependencies.
- Use bounded event-backed state machine and persistent checkpoints; task retry and cancellation safe.
- Explicit output owner and distinct handoff records; **do not call six functions “six agents” unless they have genuine task state/handoffs**.
- Simple model adapter may be added later; first graph can use deterministic processors as actual workers if accurately labeled.

**Tests:** dependency order, acyclicity, unknown task, concurrent artifact write conflict, failure, resume from checkpoint, invalid plan, plan changes on changed mentor availability, no unnecessary nodes on simple request.

**Done when:** run log proves the graph selected tasks based on input/goal, did real work and wrote versioned artifacts. No decorative agent roster.

### P0.4 — compute independently checkable analysis and plan

**Evidence Analyst:** deterministic aggregation from actual CSV; retains trainee/skill source row refs, missing/invalid flags, cohort totals. Do not infer personal diagnoses or assume a low score's cause.

**Intervention Specialist:** map **verified** gaps to explicit candidate resources/activities from `interventions.json`, with reason and relevant skill ID. Missing mapping remains unresolved, not invented. The human educator can review.

**Schedule Planner:** allocate to 3 mentors only within availability/capacity, avoid overlaps and contradictory slots. Use a deterministic feasible scheduling algorithm (greedy + constraints or small integer model), record unscheduled cases honestly. Input changes should cause a real replan. Handle timezone, duplicated mentor windows, unavailable/overfull capacity.

**Artifact Producer:** write actual CSV/MD/JSON. Communications remain *draft only*, with transparent lack of recipient when unspecified. No real LMS/Outlook/Gmail call.

**Tests:** independent expected totals, no duplicate slot/mentor conflict, changed constraints, missing skill mapping, no unsourced intervention and actual file open/parse.

### P0.5 — true independent reviewer and targeted repair (G09, highest-value evidence)

**Reviewer must use a distinct algorithm/module and re-open persisted files.** It recomputes cohort aggregation from input and checks:
- every reported gap corresponds to correct source row/threshold;
- all schedule sessions are within mentor availability and no overlapping assignment/capacity;
- references to intervention/skills exist;
- output file schema and expected artifact count; all messages are **UNSENT**;
- provenance citations point to the same admitted source digest/version.

**Fault #1:** inject an actual invalid `mentor-schedule.v1.csv` with an overlap using explicit controlled test flag in synthetic fixture. Reviewer creates real FAIL check with slot/mentor IDs. Repairer changes only necessary schedule nodes, writes `mentor-schedule.v2.csv`; Reviewer **re-opens** and independently checks PASS.

**Fault #2:** inject a genuine wrong aggregate in `performance-summary.v1.md` or backing JSON. Reviewer recomputes from raw input, reports expected/observed; targeted repair and new independent PASS.

**Additional scenario:** a mentor is now unavailable at a critical time; worker replans rather than falsely insisting a schedule exists. If no feasible assignment exists, return `PARTIAL` with unscheduled slots and blocker.

**Tests:** fault exists physically in persisted output, checker detects it, repair changes bytes, re-check passes, old version persists, repair budget exhaustion fails explicitly, false positive/negative cases, reviewer cannot self-certify without evidence.

**Done when:** a fresh run produces a JSONL trace containing actual `VERIFICATION_FAILED` → `REPAIR_SCHEDULED` → `ARTIFACT_REPAIRED` → `VERIFICATION_PASSED` tied to real file versions/digests. No pre-scripted green UI.

## 6. Prioritization against official competition rubric

The user-provided rubric has seven criteria totaling **110**: Reasoning & Planning 15, Self-Correction 20, Execution & Reliability 15, Multi-Agent Collaboration 15, EdTech Impact 15, Presentation/Q&A 20, Professionalism 10.

| Criterion | Judge-visible proof | Closest work packages |
|---|---|---|
| 15 Reasoning | Real goal-dependent DAG and changed plan after new constraint | P0.3 |
| 20 Self-Correction | Genuine failed artifact, independent detection, targeted repair/recheck | **P0.5** |
| 15 Execution | Usable persisted/reopened artifacts and reliable status | P0.2, P0.4, P0.6 |
| 15 Collaboration | Real distinct worker inputs/outputs and handoffs | P0.3, P0.4 |
| 15 EdTech impact | Education coordinator outcomes with credible evidence and pilot | P0.1, P1.2 |
| 20 Presentation/Q&A | Goal→plan→work→fail→fix→verify→deliver visible, transparent technical answers | P0.6, P1.0 |
| 10 Professionalism | Honesty, deadlines, evidence, teamwork, controlled changes | Throughout |

**110/110 is a goal, never a claimed score.** Judges evaluate live behavior, not the volume of design documents. The must-win demo centers on **actual independent self-repair**.

## 8. Release/demo readiness checklist

- [ ] All synthetic inputs, sources and artifacts have stable IDs and digests.
- [ ] First run persists actual files and a DAG; simple/complex tasks differ.
- [ ] Real verifier catches and repairs at least one fault without manual file correction.
- [ ] Both failed and repaired artifact versions are inspectable.
- [ ] A second independent edge case passes or safely blocks, no fake success.
- [ ] No external messages sent, no official grades edited, no real learner records.
- [ ] UI reflects actual backend events; source and check evidence can be inspected.
- [ ] New clone can run demo with no private SaaS credentials.
- [ ] README explains assumptions, exact commands, model/runtime choices, costs and known limitations.
- [ ] CI/evaluation run IDs match commit and demonstrated code; no invented metrics.
- [ ] On-time competition submission is verified; offline fallback labeled as recorded, not falsely live.
- [ ] Any actual live connector has separate G07 approval, tenant/resource policy, read-back and privacy review.

**Engineering completion definition:** evidence-backed, independently rerunnable runtime behavior. A diagram, code skeleton, empty database, green contract test or synthetic UI animation is **not** an E2E deliverable.
