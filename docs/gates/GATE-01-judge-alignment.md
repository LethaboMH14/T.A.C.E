# Gate 01 — Melsoft and judging evidence

**Research date:** 2026-11-10. **Status:** Public evidence and reasoned implications only; no hidden judging rubric established.

## Official requirements (binding)

The official Colleague Zero page expressly requires a real EdTech problem in teaching, learning or educational programme operations. The five criteria are **reasons, self-corrects, executes, collaborates and serves education**. Final presentation is to show the problem, a live colleague working, reasoning/correction and what comes next. **A purely universal developer agent platform is not enough**, even if sophisticated.

Source: https://hackathon-26.melsoft.org/

Inference: present understandable value and defensible engineering. Do **not** attribute a particular scoring demand to any individual. https://hackathon-26.melsoft.org/

## Suggested judging proof

**Two education requests, one engine**: a small syllabus-to-table task selecting a minimal topology, then an end-to-end learner/program support task using distinct specialist agents, context retrieval, real tool execution, independent review/correction and a persisted, re-openable artifact.

**Honesty conditions:** don't claim actual gains, arbitrary tool execution, real external sends, successful fine-tuning, accurate African-language output, multimodal video generation or fully automated agent topology unless demonstrated and tested. A generic system can be an architecture; **a real education workflow must be the submitted product proof**.
